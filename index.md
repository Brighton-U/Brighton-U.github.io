This code review examines the original Pokémon ROM Randomizer artifact and identifies opportunities for improvement that served as the foundation for the three enhancements completed during the capstone project.

## Enhancement 1: Software Design and Engineering
[Enhanced Artifact](https://github.com/reeduxx/yet-another-pokemon-randomizer/tree/enhancement-1)

  Prior to this enhancement, the project used hardcoded game definitions for each game version and generation that was supported. This meant that in order to support a new game version, the source code would have to be modified. To improve scalability and extensibility, this system was redesigned to load game definitions dynamically from external JSON files, separating the static data from the business logic. This system also allowed optional user-defined game definitions to be loaded from a designated directory. I implemented a modular loader, factory, and registry architecture to support these definitions, incorporating schema validation using Pydantic to ensure that definitions were properly structured and validated before use.
  I demonstrated my ability to evaluate and improve a system through modular architecture, data-driven design, and validation modeling. I also demonstrated professional coding practices through the use of documentation, modularized components, separation of concerns, and improved maintainability. Additionally, I was able to showcase my ability to identify, evaluate, and implement relevant Python modules to support the system architecture.
This enhancement taught me the importance of designing software for scalability and long-term maintenance. The largest challenge of this enhancement was transitioning from a previously hardcoded system to a fully data-driven architecture while maintaining compatibility. I also needed to carefully consider the structure of the project in terms of resource pathing. Another challenge involved designing a validation system robust enough to safely support the optional user provided game definitions. Implementing Pydantic models helped simplify the validation logic while improving the overall reliability and maintainability of the project.

## Enhancement 2: Algorithms and Data Structures
[Enhanced Artifact](https://github.com/reeduxx/yet-another-pokemon-randomizer/tree/enhancement-2)

  This enhancement concentrated on improving the application’s ability to efficiently process and organize game data using custom algorithms and data structures. I implemented filtering systems that allow Pokémon species to be selected according to user-defined constraints, including base stat total ranges and type restrictions. These filtering operations require efficient traversal and evaluation of collections of species data. I also designed and implemented a type-trio generation system that allows users to generate starter Pokémon based on predefined type relationships, such as the traditional grass, fire, and water trio. This required the creation of data structures to represent type combinations and algorithms capable of selecting valid Pokémon  while enforcing uniqueness and user-defined restrictions. The starter generation algorithm combines multiple filtering and validation steps to produce valid randomized results while maintaining the constraints established by the user. Two planned features that were not fully realized in this enhancement were exclusion systems for legendary Pokémon and evolutionary families. They have been partially implemented in the source code but not fully realized in the user interface.
  The filtering systems, type-trio generation logic, exclusion systems, and starter selection algorithms required careful consideration of how data should be organized and processed to efficiently meet user requirements. This enhancement also supported the outcome related to software development practices through the incorporation of automated testing through Pytest. Developing unit tests helped validate the correctness of several key features while improving the maintainability and reliability of the application.
  This enhancement provided valuable experience in designing algorithms that must satisfy multiple constraints simultaneously. One of the most important lessons I learned was the importance of carefully selecting data structures based on the requirements of the problem. For example, using sets to represent excluded Pokémon simplified validation logic and improved lookup efficiency compared to using lists alone. One challenge I encountered was ensuring that randomly selected starter Pokémon satisfied all user-defined constraints while still producing valid and varied results. The generation logic needed to account for type restrictions, base stat total limits, and uniqueness requirements. Developing a solution that handled all of these requirements required several iterations and careful testing. Another challenge involved balancing flexibility and maintainability. As additional filtering options were introduced, it became important to separate filtering logic into reusable functions rather than embedding conditions directly into the generation process. This resulted in a cleaner and more extensible design that will make future enhancements easier to implement, such as the randomization of wild and trainer Pokémon. The implementation of unit tests also reinforced the importance of verification and validation in software development. Creating tests for the game definition registry and loader helped identify edge cases and provide confidence that future modifications would not unintentionally break existing functionality.

## Enhancement 3: Databases
[Enhanced Artifact](https://github.com/reeduxx/yet-another-pokemon-randomizer/tree/enhancement-3)

  This enhancement was focused on integrating a relational database into the application to improve data organization, persistence, validation, and long-term scalability. Originally, the application loaded game definitions directly from external JSON files. While this approach did improve the flexibility and extensibility of the project, it did not demonstrate the use of database technologies. To address this limitation, a SQLite-based data layer was designed and implemented to store validated game definitions and their associated offset information in a normalized relational schema. I designed a relational schema consisting of separate tables for game definitions and related offsets, connected through foreign key relationships. I implemented uniqueness constraints to prevent duplicate records and indexes to improve lookup performance. A repository layer was also introduced to abstract database operations from the rest of the application and provide methods for inserting, retrieving, and querying game definitions. Additionally, an importer was designed to transform validated JSON definitions into database records. I also created a database manager for coordinating schema creation, data imports, and data retrieval. Finally, the database layer was integrated into the existing game registry workflow so that game definitions are validated, imported into SQLite, and then loaded from the database before being used by the application. In addition to these changes for the enhancement, I also continued to develop additional tests regarding validation coverage.
  This enhancement demonstrates my ability to design and evaluate computing solutions that solve a defined problem by introducing a database architecture that improves the maintainability, data integrity, and scalability of the project. It also demonstrated my use of innovative techniques and tools in computing practices through the integration of SQLite, relational modeling, automated validation, and repository-based data access. Currently, the database implementation operates in memory and is recreated when the application starts rather than serving as a persistent storage solution. The database also only supports game definitions. I would like to extend the database to include tables for Pokémon, moves, and items to further increase the modularity, extensibility, and maintainability of the application.
  Throughout the enhancement process, I gained a deeper understanding of database design and integration. An important lesson I learned was the value of separating data persistence concerns from business logic through the use of repository and manager patterns. I also gained practical experience working with SQLite, relational database concepts such as normalization, foreign keys, indexing, and uniqueness constraints. A significant challenge involved integrating the database layer without disrupting the existing architecture developed in the previous enhancements. Automated testing also played a critical role throughout the process by helping identify validation gaps, implementation errors, and integration issues before they affected the application.
